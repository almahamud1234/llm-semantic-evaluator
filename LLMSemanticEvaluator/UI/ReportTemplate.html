Problem & Goal

Problem: When a software team builds a product on top of an LLM (e.g. a customer-support chatbot or a document-summarisation service), they cannot manually verify thousands of outputs to check whether the model is reliable. Traditional assert output == expected testing fails because LLMs are non-deterministic — the same prompt can return semantically correct but differently-worded answers on every run.

Goal: Automatically evaluate whether an LLM answers correctly across %%TOTAL%% test cases and %%TOTAL_RUNS%% total runs, using two independent semantic validators — embedding cosine similarity and an LLM-as-a-judge (G-Eval style) — and produce an actionable reliability verdict per category that tells the customer which task types are safe to deploy.

Strategy: Each test case is executed %%RUNS_PER_TEST%% times to account for non-determinism. A run passes if either the embedding similarity ≥ %%EMB_THRESHOLD%% or the judge score ≥ %%JUDGE_THRESHOLD%%/10 (OR logic). A test case passes if at least %%MIN_PASS_RUNS%% of %%RUNS_PER_TEST%% runs pass (majority vote). This tolerates one outlier run without masking a genuinely unreliable model.

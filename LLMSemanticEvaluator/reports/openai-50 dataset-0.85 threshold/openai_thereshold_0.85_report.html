Problem & Goal

Problem: When a software team builds a product on top of an LLM (e.g. a customer-support chatbot or a document-summarisation service), they cannot manually verify thousands of outputs to check whether the model is reliable. Traditional assert output == expected testing fails because LLMs are non-deterministic — the same prompt can return semantically correct but differently-worded answers on every run.

Goal: Automatically evaluate whether an LLM answers correctly across 50 test cases and 150 total runs, using two independent semantic validators — embedding cosine similarity and an LLM-as-a-judge (G-Eval style) — and produce an actionable reliability verdict per category that tells the customer which task types are safe to deploy.

Strategy: Each test case is executed 3 times to account for non-determinism. A run passes if either the embedding similarity ≥ 0.85 or the judge score ≥ 8/10 (OR logic). A test case passes if at least 2 of 3 runs pass (majority vote). This tolerates one outlier run without masking a genuinely unreliable model.

Key Insights

Why is the average embedding score low (0.57) yet the pass rate is 100.0%?
Short expected outputs produce low cosine similarity against full-sentence LLM responses because the vector spaces do not overlap well at different lengths. This is a known limitation of embedding-based evaluation. The LLM judge correctly scores these as high quality, and the OR logic ensures they still pass. 50 of 50 tests passed via the judge validator alone, confirming the dual-validator design is essential.
Why run each test 3 times?
LLMs are non-deterministic — the same prompt can produce different wording across runs. Running 3 times and requiring 2/3 to pass (majority vote) eliminates single-run flukes without being too strict. Consistent results across all runs indicate a stable, reliable model for that task type.
